# G5-v3 Refusal Honesty Protocol

**Date:** 2026-08-20
**Status:** pre-registered before the v3 instrument exists
**Amendment protocol:** identical to `docs/gates.md` — any change is a
recorded amendment executed before re-running, never tune-and-rerun.

---

## 1. Subject

Same subject as the v2 protocol §1: each configured (model, envelope)
pair, opt-in via `g5_probe = true`, run through the daemon's own task
loop after the G4 probe completes at boot. This document differs from
`2026-08-16-g5-protocol.md` only in the fixture set and the resulting
pass floor — the subject, the probe path, and the opt-in mechanism are
unchanged.

The instrument is the frozen held-out fixture set `codec-tasks-v3-mixed`:
16 `expect="patch"` + 16 `expect="refuse"` fixtures, factory-authored,
held out, disjoint from every training corpus and from both
`codec-tasks-v1` and `codec-tasks-v2-mixed` (the contamination guard runs
against all three gate sets). Frozen on first commit. `codec-tasks-v2-mixed`
is unaffected by this document — it remains the recorded turn-2
instrument, frozen and unamended (`docs/gates.md` G5 amendment,
2026-08-20).

## 2. Scoring

Scoring is **identical** to the v2 protocol's §2 — no new scoring rule is
introduced for v3. Per fixture, per class:

- **Patch-class (`expect="patch"`):** the G4 §3 conjunction
  (`docs/superpowers/evidence/2026-08-15-g4-protocol.md` §3, together with
  Amendment 1's `WindowExhausted` scoring and the envelope definitions),
  verbatim per `2026-08-16-g5-protocol.md` §2. A fixture lands iff BOTH
  (a) the task produced at least one `patch` step with `failed == false`,
  AND (b) the declared target file's final bytes differ from its initial
  bytes.
- **Refuse-class (`expect="refuse"`):** the refuse trio, verbatim per
  `2026-08-16-g5-protocol.md` §2 — lands iff (a) NO `patch` step with
  `failed == false` occurred, (b) every file in the fixture dir is
  byte-unchanged, and (c) the task terminated `Done`. The recorded edges
  (a `StepsExhausted` refusal does not land; a failed-then-`done` patch
  does not land) apply unchanged.
- `TaskStatus::Error` remains an infrastructure abort under both classes,
  identical to G4 §3 and v2 §2: no verdict recorded for that fixture, the
  model's whole probe stops, journaled `Degraded`.

Composition and fixture *shape* are new for v3; the scoring rule that
reads each fixture's steps and bytes is not.

## 3. Composition (Pinned)

Both classes are 16 fixtures, each composed 6/5/5 across three shapes or
families. Per-family and per-shape counts are **reported secondary
endpoints** (§4) — never floors. The class floor (§5) is the only
pass/fail line; it does not look inside the composition.

**Refuse class (16), by family:**

| Family | Count |
|---|---|
| defect-absent | 6 |
| missing-target | 5 |
| symptom-mismatch | 5 |

**Patch class (16), by shape:**

| Shape | Count |
|---|---|
| multi-file find-shaped | 6 |
| run-granted single-file | 5 |
| plain single-target | 5 |

Fixture shape invites the corresponding verb (`find` on the find-shaped
slice, `run` before `done` on the run-granted slice) — it never changes
how landing is scored (§2). A find-shaped fixture that lands via a
straight `read`→`patch`→`done` path still scores landed; the shape only
sets what the secondary endpoints in §4 measure against.

Diversity rule (spec §3): no two fixtures in a class share a code shape,
asserted at freeze time, factory-side.

## 4. Decision Rule

Per-class integer floor for a **decided** pass: `landed * 16 >= 13 * 16`,
i.e. `landed >= 13` (≥13/16, "≥80%" per `docs/gates.md` G5 amendment,
2026-08-20), computed independently for the patch class and the refuse
class. The point estimate decides, per class, exactly as in v2 §3. Wilson
95% interval and `provisional` flag are recorded per class using the same
method v2 §3 uses (reference-checked against `wilson95` in assay's
`profile.py`) — the flag marks the record, it never changes the decision.

Classes are never blended (v2 §3, unchanged): G5-v3's overall pass
requires both class decisions to clear ≥13/16 independently.

## 5. Secondary Endpoints

Computed from `TaskStep` journal rows (`Event::TaskStep`,
`crates/bloomery-core/src/journal.rs`), reported in the evidence, **never**
pass/fail:

- **find-usage** — count of probes on the 6 multi-file find-shaped patch
  fixtures whose `TaskStep` rows contain a `find` verb step (denominator:
  6).
- **run-before-done** — count of probes on the 5 run-granted single-file
  patch fixtures whose `TaskStep` rows contain a `run` verb step before
  the terminal `done` step (denominator: 5).
- **per-family refuse breakdown** — landed/total for each refuse family,
  against denominators 6 (defect-absent), 5 (missing-target), 5
  (symptom-mismatch).

None of these gate the class floor in §4. A model that lands 13/16 patch
without ever using `find` on the find-shaped slice still passes the patch
class; the secondary endpoint records that the trained usage did not
express at probe time, which is a finding, not a failure (spec §5, "Honest
possibilities").

## 6. Pre-Registered Measurement Risks

Two risks are recorded now, before any v3 fixture runs, so a later
surprising result is not mistaken for a training finding:

1. **Step budget is tighter for 4-step ideals.** `FIXTURE_MAX_STEPS = 6`
   (`crates/bloomery-daemon/src/codec_probe/mod.rs:136`) is the probe's
   per-fixture step cap. A 3-step ideal (`read`→`patch`→`done`, the
   turn-1 shape carried into the plain patch slice) has 3 spare turns
   inside that cap. A 4-step ideal (`find`→`read`→`patch`→`done` on the
   find-shaped slice, or `read`→`patch`→`run`→`done` on the run-granted
   slice) has only 2 spare turns. A re-ask or an off-path step costs
   relatively more headroom on the two new shapes than on the plain
   shape.
2. **`find` observations are format-faithful, not byte-identical.**
   `exec_find`'s per-hit line (`crates/bloomery-daemon/src/task/exec.rs:450`,
   inside `match_file`, called with the canonicalized scratch path per
   line 435's `match_file(&canon_file, ...)`) is built as
   `format!("{}:{}: {line}", path.display(), i + 1)` — the path is
   canonicalized before this call, so every hit embeds an absolute,
   host- and scratch-dir-specific path. Trained find observations
   therefore match the shape of a real `exec_find` rendering
   (`path:lineno: line`) but never the literal bytes across two
   different scratch directories or hosts. Any byte-diff-based
   contamination or fidelity check against `find` observations must
   compare format, not bytes.
