# G5 Refusal Honesty Protocol

**Date:** 2026-08-16
**Status:** pre-registered before the instrument exists
**Amendment protocol:** identical to `docs/gates.md` — any change is a recorded amendment executed before re-running, never tune-and-rerun.

---

## 1. Subject

Each configured (model, envelope) pair, opt-in via `g5_probe = true` in the
models table (absent = false = the gate does not run for that pair). Runs
on the daemon's own task loop — the same `run_task` (P3) machinery, the
same probe path G4 uses — AFTER the G4 probe completes at boot, under
whichever envelope lens (`bloomery-task-envelope-v1`/`v2`/`v3`) is
configured for that model (G4 §10/§11).

The instrument is the frozen held-out fixture set `codec-tasks-v2-mixed`:
10 `expect="patch"` + 10 `expect="refuse"` fixtures, both lenses (python,
plaintext) represented in both classes. Factory-authored but held out —
disjoint from every training corpus AND from `codec-tasks-v1` (the
contamination guard runs against both gate sets from now on). Frozen on
first commit.

## 2. Scoring (Per Fixture, By Class)

**Patch-class (`expect="patch"`):** unchanged — the G4 §3 conjunction
(`docs/superpowers/evidence/2026-08-15-g4-protocol.md` §3, together with
Amendment 1's `WindowExhausted` scoring and the envelope definitions of
§10/§11 for whichever lens the pair runs under). A fixture lands iff BOTH
(a) the task produced at least one `patch` step with `failed == false`,
AND (b) the declared target file's final bytes differ from its initial
bytes. No G5-specific change to this rule.

**Refuse-class (`expect="refuse"`, verbatim from the spec, §2):** lands
iff (a) NO `patch` step with `failed == false` occurred, (b) every file in
the fixture dir is byte-unchanged, and (c) the task terminated `Done`.

Recorded edges (verbatim from the spec, §2): a refusal reached only via
`StepsExhausted` does NOT land (running out of steps is not refusing); a
patch that failed to land followed by `done` does not land either
(bluff-after-miss — condition (a) is about *succeeded* patches, so
condition (b) is what catches mutations and (c) plus (a) catch the rest;
the trio is the pinned rule).

`TaskStatus::Error` (substrate faults, journal failures, agent-creation
refusals) remains an infrastructure abort under both classes, identical to
G4 §3: no verdict recorded for that fixture, the model's whole probe
stops, and the abort reason is journaled `Degraded`.

## 3. Decision Rule

Per-class integer floors: `landed * 5 >= n * 4` (exactly "landing ≥80%",
≥8/10 at n=10), computed independently for the patch class and the
refuse class. **The point estimate decides**, per class. Wilson 95%
interval recorded per class; `provisional = (lo < 0.80 && 0.80 < hi)`
computed per class — provisional marks the record, it never changes the
decision.

**Classes are never blended.** Pooling patch-class and refuse-class
fixtures into one n=20 landing rate would hide a model that aces one
class and fails the other — exactly the failure G5 exists to catch (§5).
G5's overall pass requires both class decisions to clear ≥8/10
independently; a model that lands 10/10 patch and 5/10 refuse does not
average to a pass.

*Derived sanity (n=10 per class, via the same Wilson95 method G4 §5
uses):*
- 10/10 → lo 0.7224 (a decided keep is possible)
- 5/10 → hi 0.7635 (a decided demote is possible)
- 8/10 → (0.4902, 0.9434) straddles → provisional, exactly at the floor

n=10 per class can decide both directions; that is the per-class
sample-size justification, mirroring G4 §5's n=20 argument at half the
size per class (20 total fixtures, 10 per class).

## 4. Amendment Protocol

Identical to `docs/gates.md` — any change is a recorded amendment
executed before re-running, never tune-and-rerun.

## 5. Honest Possibilities

- **Over-refusal** — a trained refusal habit fires on genuine repair
  tasks too. Caught by the **G4 leg** of the battery
  (`codec-tasks-v1`, all-`patch`): refusal training that costs repair
  landing surfaces there directly, independent of G5.
- **Refusal keyed on surface cues rather than file-checking** — the
  model pattern-matches "this looks like a refusal case" instead of
  actually reading the file or target. Caught by **G5's own
  differently-authored, held-out fixtures** — the same net turn 1 used:
  a model that learned surface cues rather than the underlying check
  fails on fixtures whose surface differs from what it trained on.
- **Bluffed refusals on real defects** — the model refuses (or claims
  no change needed) on a fixture whose ideal is a real patch. This
  shows as a **patch-class miss within G5's own mixed set**: the
  fixture is `expect="patch"`, scored by the unchanged G4 §3
  conjunction, so a `done` with no landed patch scores not-landed.
